# 将网页程序打包成 Android APK / Packaging a Web App into an Android APK

本文说明如何把 `www/` 目录下的网页应用打包为 Android APK，以及如何替换成其他网页程序。

This document explains how to package the web app in `www/` into an Android APK, and how to replace it with another web app.

## 环境 / Requirements

- Node.js 18+
- JDK 17
- Android SDK（compileSdk 34）

如果仓库根目录下存在 `android-env/`（本地 JDK + Android SDK），`build_apk.ps1` 会自动使用它，否则读取系统环境变量 `JAVA_HOME`、`ANDROID_HOME`。

If an `android-env/` directory (local JDK + Android SDK) exists in the repo root, `build_apk.ps1` will use it automatically; otherwise it reads the `JAVA_HOME` and `ANDROID_HOME` environment variables.

## 一键构建 / One-click Build

```powershell
.\build_apk.ps1
```

构建完成后，APK 位于 / After the build, the APK is at:

```text
Calculator-debug.apk
```

等价的手动步骤 / Equivalent manual steps:

```powershell
npx cap sync android
cd android
.\gradlew.bat assembleDebug --no-daemon
```

## 替换成其他网页程序 / Replace with Another Web App

1. 把新程序的所有网页文件复制到 `www\` / Copy all web files of the new app into `www\`.
2. 如果新程序是 React/Vue 等前端项目，先执行它自己的构建命令，再把 `dist/` 或 `build/` 的内容复制到 `www\` / If the new app is a React/Vue front-end project, run its own build first, then copy the contents of `dist/` or `build/` into `www\`.
3. 删除网页里所有在线 CDN 引用，把 `mathjs`、`katex`、图标、字体、图片等资源复制到 `www\`，并改成相对路径 / Remove all CDN references, copy resources such as `mathjs`, `katex`, icons, fonts, and images into `www\`, and switch to relative paths.
4. 修改 `capacitor.config.json` 中的 `appId` 和 `appName` / Change `appId` and `appName` in `capacitor.config.json`.
5. 重新执行上面的构建步骤 / Run the build steps again.

## 离线使用要求 / Offline Requirements

App 安装后不会自动联网，所以必须把网页需要的所有 JS、CSS、字体、图片都放进 `www\` 目录，不能依赖 CDN。

The app does not connect to the network automatically, so all JS, CSS, fonts, and images must be placed in `www\`; do not rely on CDNs.

## 适合这样打包的程序 / What Can Be Packaged This Way

- 纯 HTML/CSS/JavaScript 程序：直接打包 / Pure HTML/CSS/JavaScript apps: package directly.
- 有浏览器前端构建产物的 SPA 程序：构建成静态文件后打包 / SPAs with browser build output: build static files first, then package.
- 依赖 Node.js 后端的程序：不能直接这样打包，需要先部署后端服务器，网页通过 HTTPS 调用接口 / Apps that depend on a Node.js backend cannot be packaged this way; deploy the backend first and call it over HTTPS.
