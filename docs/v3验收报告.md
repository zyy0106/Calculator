首轮 56/69，13 项失败全部是我写的断言问题，已修正：
- K 段 3 条：把第 3 行（sqrt/sq/ln）与第 4 行（sin/cos/tan）的 id 期望写反了。
- L 段 9 条：期望选项高 = 静止按钮高 × 2/3（56.66×2/3 = 37.77px），实测 35.5px。原因是按住时 `button:active { transform: scale(0.94) }` 生效，气泡按“按下状态”的按钮矩形（53.26px）计算，53.26×2/3 = 35.5px。断言改为用按住时的按钮高度。这符合实现的设计，但与“按钮高 × 2/3”的字面描述有 6% 偏差，列入风险。
- A 段 1 条：用 `.katex-html` 整个容器宽度（340px，被 width:100% 撑开）做比较，改为锚点 0→5 跨度对比 KaTeX 单独渲染宽度。

## 5. 遗留风险

继承自上游：
- 360×640 变量页：键盘被 `fitKeyboard()` 缩到 267px 宽，cell 39.5px，按键偏小。
- 公式屏下限约 90px（实测 360×640 函数页 91.2px、变量页 92.1px），长公式或双行显示空间紧张。
- 运算符旁锚点仍有约 5.38px 宽（KaTeX 二元运算符间距所致）；纯数字锚点为 0。
- 内核仍接受 `t` 作为合法变量（`VARS.t`、`var_t` 编辑器保留），宿主已无 t 的入口与取值，输入 t 计算会报变量未定义。
- 真机 Android 触摸、`pointercancel`、系统长按菜单与 WebView 滚动冲突均未验证；本次全部为桌面 Edge 鼠标模拟的 pointer 事件。
- `suite.js`（v1）依赖仓库外 harness，已无法运行。

本次新发现：
- 气泡选项高度按“按下时（scale 0.94）”的按钮矩形计算：420×860 下 35.5px，而静止按钮高 × 2/3 = 37.77px。功能无影响；若要严格按静止高度，可在 `tools/longpress-bubble.js` 的 `showBubble` 里改用 `button.offsetHeight` 计算 `ih`（需同步内联副本）。判定：非功能 bug，供上游决定。
- 仓库文档中找不到 N3 的定义（见第 1 节）。
- suite-v3 依赖 Playwright 时序（500ms 实时等待），在慢机器上可能出现时序抖动。
