## 原理与取舍
- **贴顶的原因**：v3 的显示区块是 `flex: 1 1 auto`，占满了 `.screen` 的所有剩余高度。`.katex-display` 是块级元素，在这个块里从顶部开始排。`align-content:center` 对 block 容器内的 KaTeX 行没有可靠效果。
- **方案**：把显示区块改成 `flex: 0 1 auto`，高度等于内容高度。这样公式块和结果行组成一组，由 `.screen` 已有的 `justify-content:center` 整体居中，结果行不会被挤出去。
- **KaTeX 的 margin 和基线**：居中的对象是外层盒子，不是基线，所以 `\frac`、`\int` 撑高的行盒（strut 和 vlist depth）全部算在内容高度里，不会产生不对称。`.katex-display` 上下各有 2px margin，结果行的下边距设为 2px，与之对称（上边距仍为 5px，与 v3 一致）。
- **高公式**：组的高度超过 `.screen` 时，显示区块按 `flex-shrink` 缩小，变为可纵向滚动（已有 `overflow-x:auto`，所以 y 方向会算成 auto）。同时加上 `ec-tight` 类，去掉 11px 的 margin。`centerDisplayY` 把初始 `scrollTop` 设为让 `.katex` 盒子居中；如果光标会被遮住，则让光标保持可见。`scrollHeight - clientHeight ≤ 1` 只是取整误差，不当作滚动处理。
- **没有选择“让显示区增高”**：显示区增高要么占用键盘高度，要么造成页面溢出，会破坏 v3 已验收的约束。
- **已知的度量取舍**：任务要求“`.katex` 上下边距差 ≤ 2px”，同时要求“公式与结果整体居中”，在有结果行时两者无法同时满足。本次以整体居中为准，下表同时给出三种口径。
