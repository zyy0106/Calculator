### 1.3 suite.js 不稳定用例调查

I4b 曾报告基线 151–152/153，失败项为常量用例 `NA*qe` 与 `g_n*2`。

本次运行：

| 轮次 | 方式 | 通过数 | 失败项 |
|---|---|---|---|
| 1–5 | 串行 | 153/153（每轮） | 无 |
| 并行 1–6 | 6 个实例同时运行（加压） | 153/153（每个） | 无 |

未能复现。可能机理（已证实存在，但未证实就是当时的失败原因）：`suite.js` 的 `tapConst` 用真实计时器，`mouse.down` → `waitForTimeout(60)` → `page.evaluate` → `mouse.up`。页面常量格 `CONST_LONG_MS=450`（index.html 第 2845 行），按住达到 450 ms 即判为长按，只显示数值、不插入常量。最小演示（真实计时器、NA 格）：按住间隔 73/402/459 ms 时插入 `6.02214076e23`，478/543 ms 时编辑器为空。若测试机在按下与松开之间卡顿约 400 ms，常量不会被插入，结果就会与期望不符。这属于测试时序问题，不是 index.html 缺陷：≥450 ms 不插入是设计行为，没有可指出的功能错误和最小失败例，所以**未修改 index.html**。
结论：**已知不稳定，原因未证实（最可能为测试时序）**。建议（未实施）：`suite.js` 改用 `page.clock` 或缩短按压路径。

## 4. 已知限制

- 积分方程不支持 Fredholm/Volterra 方程、多个未知参数、复数根、反常积分、自适应积分；偶重根（G(x) 只触及 0 而不变号）扫描不到；求解期间界面同步阻塞（默认参数耗时 3–19 ms）。
- 自动右滚：光标在最末端时，右侧 24 px 余量会被最大滚动量夹掉，光标超出可视边缘约 0.23 px（测试容差 1 px）。
- `tools\suite.js` 仍依赖 `%TEMP%\webcasio-test\harness.js`（I2 改过），不是仓库内文件，换机器无法直接复现。本任务按要求未改 `suite.js`；仓库内已有同内容的 `tools\harness.js`，`suite-v2.js` 用它。
- `playwright-core` 不在仓库依赖中。`suite-v2.js` 先尝试正常 `require`，再尝试环境变量 `PW_NODE_MODULES`，最后用 `%TEMP%\webcasio-test\node_modules`；`harness.js` 写死了 Edge 路径 `C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`。
- suite.js 的常量用例可能因真实计时器而偶发失败（1.3）。
